# Handover — doc-extract

For whoever owns runtime. This document exists so the split of
responsibilities is explicit rather than assumed.

---

## What this is

An MCP server. PDF in, structured JSON out. No database driver, no outbound
writes, every tool annotated read-only. It is one node in a MagOneAI
workflow; insert, redaction and chat are separate nodes.

- Python 3.12, ~2,000 lines, no system dependencies (`pdfplumber` is pure
  Python, so the image is `python:3.12-slim` plus pip installs).
- Stateless HTTP. Scales horizontally, no session affinity, restart-safe.
- Runs as a non-root user. 25MB input cap. PDF magic-byte check before parse.

---

## Run it in two minutes

```bash
cp .env.example .env          # set DOC_EXTRACT_TOKEN
docker compose up --build
python scripts/smoke_test.py http://localhost:8000 $DOC_EXTRACT_TOKEN
```

`scripts/smoke_test.py` is the acceptance gate for any environment. It checks
reachability, that `/health` answers **without** auth (platform probes need
this), that `/mcp` **rejects** unauthenticated calls, that a real MCP client
can discover the tools, and that an end-to-end extraction returns populated
content. Non-zero exit means do not register the URL yet.

Pass a PDF as a third argument to include the extraction check.

---

## What it needs from the platform

| Requirement | Detail |
|---|---|
| **HTTPS ingress** | MagOneAI calls it over the network; TLS terminated upstream |
| **`DOC_EXTRACT_TOKEN`** | Server-side env var. Server refuses to start on HTTP without it |
| **Health probe** | `GET /health`, unauthenticated, returns loaded profiles |
| **Egress** | Only if workflows send `source_type="url"`; not needed for base64 |
| **Memory** | ~256MB is comfortable; parsing is CPU-light and short-lived |
| **Persistence** | None. Nothing is written except a temp file per request |

No database credentials. This server never touches Neon — that is the next
node's job, and keeping it that way is deliberate.

---

## Environments and the token

One token per environment, generated by whoever owns that environment:

```bash
openssl rand -hex 32
```

It should reach the server as an injected env var and reach MagOneAI as a
stored connection secret. It should not appear in the repo, in a chat
message, in a ticket, or in the workflow canvas — a token routed through the
canvas ends up in run logs.

`.env` is gitignored. `.env.example` carries the shape, never a value.

---

## Registering in MagOneAI

Once smoke tests pass:

1. Add an MCP integration pointing at `https://<host>/mcp`.
2. Auth header: `Authorization: Bearer <token>`.
3. Set `max_iterations` ≈ 15 — one call on the happy path, but the review and
   onboarding branches chain more.
4. Workflow branches on the `status` string: `ok`, `needs_review`,
   `parsed_without_profile`, `profile_mismatch`, `no_text_layer`, `error`.

## Operating it

**Adding a vendor format is a config change, not a deploy.** Profiles are
YAML, mounted read-only in compose. Drop a file in `profiles/`, then:

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" https://<host>/admin/reload-profiles
```

A malformed profile is isolated — it lands in `load_errors` and the others
keep working. `/health` reports them.

**Logs** go to stdout, one line per extraction with the resulting status.

**Failure modes are returned, not thrown.** A bad PDF, a changed report
layout, or an unknown format all come back as a `status` plus a `hint`. The
server should not be crash-looping; if it is, that is a real bug.

## Verifying a change

Six suites, all runnable without any infrastructure:

```bash
python tests/test_samples.py      # the two real statements + failure paths
python tests/test_adversarial.py  # synthetic: wrap depth, 5–16pt, shadow text
python tests/test_detection.py    # every validation check actually fires
python tests/test_content.py      # full-document extraction, profiled or not
python tests/test_robustness.py   # format drift: renamed/added/removed columns
python tests/test_multipage.py    # header-once, page-break splits, mixed sizes
```

They are plain scripts with exit codes — drop them into CI as-is. Only extra
dependency is `reportlab`, used to synthesise test PDFs.

## Known limits, stated up front

- **Scanned PDFs are not handled.** They return `no_text_layer` cleanly. The
  OCR tier is designed but deliberately not built until the document
  inventory shows scans exist.
- **Ageing bucket labels are verified on two real documents**, both landing in
  near buckets. Run a statement with genuine 90+ ageing before trusting the
  bucket mapping in production.
- **A second, different table on a later page** could be mis-parsed if the
  header is absent and its rows resemble the first table's shape. Unrelated
  prose pages are correctly skipped.
- **Everything beyond the two real PDFs is synthetic.** The test matrix is
  good evidence, not proof. Twenty to thirty real documents is the next step.
